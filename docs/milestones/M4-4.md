# M4-4. 오버레이를 네이티브 dialog로
> 마일스톤: M4 · 상위: [M4.md](M4.md)
> 상태: ✅ 2026-11-13
## 왜 필요한가
- 설정 시트·선택 시트·보상 창이 `div` + `fixed inset-0`이라 뒤 화면이 비활성화되지 않고 포커스가 갇히지 않는다. 설정 시트와 보상 창은 `role`과 이름도 없다.
- 네이티브 `<dialog>` + `showModal()`은 뒤 화면 비활성화, 포커스 가두기·복귀, Esc 닫기를 브라우저가 처리한다 (modern-web-guidance `dialog`).
## 정해진 것
- 대상은 SettingsSheet, PickerSheet, RewardModal 3개 (2026-11-13 사용자, AR)
- Tour는 제외: 시계·하단 버튼을 `z-50`으로 어둠막 위에 올리는 구조라 최상위 레이어인 dialog와 안 맞는다. Burst(연출), 도감·짤 만들기(전체 화면)도 제외
- 열고 닫히는 방식은 그대로: 시트 2개는 바깥 탭으로 닫히고, 보상 창은 버튼으로만 닫힌다
- 토스 뒤로가기 `useTossBack`은 그대로 (M4-2)
## 제약
- `closedby="any"`(바깥 탭 닫기)는 Safari 미지원 → 토스 iOS 웹뷰용으로 클릭 좌표 판정 대체 코드를 넣는다 (출처: modern-web-guidance `light-dismiss-a-dialog`)
- 뒤 화면 스크롤 방지는 `overscroll-behavior: contain`만 쓴다. `html`/`body`에 `overflow: hidden`은 안 쓴다. Safari에서는 내용이 넘칠 때만 막히는 점진적 향상 (출처: `prevent-page-scroll-under-modal-dialog`)
- `<dialog>`에 `role="dialog"`·`aria-modal`·포커스 트랩을 따로 넣지 않는다
## 작은 판단
- 세 곳이 같은 코드(열기, 닫힘 이벤트, 대체 코드)를 쓰므로 `Modal.jsx` 하나로 묶는다
- StrictMode가 effect를 두 번 돌리면 첫 `close()`의 close 이벤트가 다시 열린 dialog에 도착한다 → 열려 있으면 무시
- 초기 포커스는 창 자체(`tabIndex={-1}` + `focus()`). 브라우저 기본(첫 버튼)으로 두면 탭 없이 열리는 보상 창의 "닫기"에 포커스 테두리가 보였다
