# M4.1-2. 저장 뒤 전면 광고 연결
> 마일스톤: M4.1 · 상위: [M4.1.md](M4.1.md)
> 상태: 🔨 진행 중 (광고 그룹 ID와 실제 기기 확인 대기)
## 왜 필요한가
- M4.1 완료 조건: 실제 토스 앱에서 짤을 저장하면 전면 광고가 뜨고, 닫으면 짤 만들기 화면으로 돌아온다.
## 정해진 것
- 저장 순서는 그대로 두고, 광고는 저장이 끝난 뒤에 띄운다 (D-14, D-16)
- 하루 1번(`bleep:lastAd`), 공유를 취소하면 안 띄움 (D-16)
- 광고를 불러오거나 띄우다 실패해도 저장 결과는 그대로다. 조용히 넘어간다
- 미리 불러오기는 짤 만들기 화면을 열 때. 오늘 이미 봤거나 `isSupported()`가 false면 부르지 않는다 (2026-11-14 사용자, AR)
- 저장이 끝났는데 아직 안 불러와졌으면 기다리지 않고 넘어간다. `lastAd`도 안 쓴다 (2026-11-14 사용자, AR)
## 손댈 곳 (예상)
- `src/lib/ads.js` (새 파일): 지원 여부 확인, 미리 불러오기, 띄우기, 하루 1번 판단
- 짤 만들기 화면의 저장 처리부 (저장 성공·공유 완료 뒤에 띄우기 호출)
- `scripts/qa.cjs`, `docs/qa/QA_CHECKLIST.md`: 토스 흉내 환경에서 광고 SDK를 가짜로 바꿔 확인
  - T-28: 광고가 실패해도 저장은 성공
  - T-29: 하루 2번째 저장과 공유 취소 때는 광고를 안 띄움

## 작은 판단
- `lastAd`는 `show`를 부를 때 쓴다. 띄우기에 실패해도 그날은 다시 시도하지 않는다 (단순, 광고 반복 요청 방지)
- 브라우저에는 SDK가 없어서 광고를 부르지 않는다. QA는 `window.__BLEEP_ADS__`로 가짜 SDK를 넣는다
- 저장 알림(`alert`)이 끝난 뒤에 광고를 띄운다 (저장 완료를 먼저 알림)
- [ ] Stack: 해당 없음 (SDK는 이미 설치됨)
