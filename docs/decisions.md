## D-01. 화면 스택
- 결정: React 19 + Tailwind CSS v3.4 + Vite, 이미지 캡처는 html2canvas 1.4.
- 이유: 웹뷰 미니앱에 가볍고 익숙한 조합.
- 대안과 기각 이유: Tailwind v4는 기본 색이 `oklch()`라 html2canvas 1.x가 파싱하지 못해 캡처가 실패한다.

## D-02. 서버리스 (2026-11-13 사용자)
- 결정: 백엔드를 두지 않는다.
- 이유: 랭킹·알림·동기화가 없어서 서버가 필요 없다.
- 대안과 기각 이유: 서버를 두면 운영 비용과 심사 범위가 늘어난다.

## D-03. 게스트 (2026-11-13 사용자)
- 결정: 로그인 화면 없이 바로 쓰고, 데이터는 기기 localStorage에만 둔다.
- 이유: 서버가 없고 진입 장벽을 없앤다.
- 대안과 기각 이유: 토스 계정 연동은 서버가 필요하다. 대신 기기를 바꾸면 도감이 사라진다 (spec.md 11장).

## D-04. 범위 밖 (2026-11-13 사용자)
- 결정: 랭킹, 알림, 서버 동기화는 만들지 않는다.
- 이유: 모두 서버가 필요하다 (D-02).
- 대안과 기각 이유: 없음.

## D-05. 디자인 시스템 (2026-11-13 사용자)
- 결정: Tailwind로 만들고, 앱인토스 심사에서 TDS를 요구하면 그때 바꾼다.
- 이유: 요구 여부를 아직 모른다.
- 대안과 기각 이유: 처음부터 TDS를 쓰면 html2canvas 호환을 다시 확인해야 한다.

## D-06. 근무일 (2026-11-13 사용자)
- 결정: 주말·휴일 구분 없이 매일 근무일로 본다.
- 이유: 가장 단순하다.
- 대안과 기각 이유: 요일 설정은 설정 화면과 상태 계산이 복잡해진다.

## D-07. 야간 근무 (2026-11-13 사용자)
- 결정: 퇴근 ≤ 출근이면 근무 시간은 working, 퇴근부터 그날 출근 전까지 off. before는 없다.
- 이유: 그전 코드는 야간 근무자가 off가 되지 않아 보상을 못 받았다.
- 대안과 기각 이유: 퇴근 직후를 before로 보면 보상 시점이 없다.

## D-08. 카운트다운 타이머
- 결정: 다음 정각 초에 맞춘 `setTimeout`을 이어 걸고, 매 틱 `Date.now()`로 다시 계산한다. `visibilitychange`로 가려지면 멈춘다. 매초 다시 그리는 범위는 `memo`로 감싼 `<Countdown>`.
- 이유: 드리프트와 백그라운드 탭 지연을 피하고 리렌더를 줄인다.
- 대안과 기각 이유: `setInterval`은 밀리고, 백그라운드에서 몰아서 실행된다.

## D-09. 퇴근 보상
- 결정: 근무일 키(퇴근 시각의 날짜)를 `bleep:lastReward`에 저장해 1번만 준다. 안 모은 단어 중 common 55 / uncommon 25 / epic 12 / unique 6 / legendary 2 가중치(2026-11-13 사용자: 4등급 → 5등급)로 뽑고, 다 모았으면 전체에서 뽑는다.
- 이유: 수집 진행이 보이게 한다.
- 대안과 기각 이유: 완전 무작위는 중복이 많아 모으는 재미가 줄어든다.

## D-10. 보상 누적 없음 (2026-11-13 사용자)
- 결정: 앱을 열지 않은 날의 보상은 사라진다.
- 이유: 가장 단순하다.
- 대안과 기각 이유: 누적은 날짜 계산과 여러 장 보상 화면이 필요하다.

## D-11. 단어 저장 방식 (2026-11-13 사용자)
- 결정: 단어는 많을수록 좋고, 정적 JSON을 코드에 포함한다. 수천 개를 넘어 첫 로딩이 느려지면 별도 JSON을 불러오는 방식으로 바꾸고, 형식은 그대로 둔다.
- 이유: 서버가 없고, 수천 개까지는 번들에 넣어도 충분히 작다.
- 대안과 기각 이유: 원격 DB는 D-02와 맞지 않는다.

## D-12. 단어 수위 (2026-11-13 사용자)
- 결정: 순화 비속어(minced oath), 장난스러운 욕(playful profanity), 순한 욕(soft swear)만 넣는다. 실제 욕설·비하·혐오 표현은 넣지 않는다.
- 이유: 앱인토스 심사 수위.
- 대안과 기각 이유: 없음.

## D-13. 세부 검수 기준 보류 (2026-11-13 사용자)
- 결정: 앱인토스 콘텐츠 기준을 확인한 뒤 정한다. 그전까지는 지금 목록을 유지한다.
- 이유: 기준을 아직 모른다.
- 대안과 기각 이유: 추측으로 기준을 세우면 다시 해야 할 수 있다.

## D-14. 짤 캡처와 저장
- 결정: 캡처 영역에는 외부 이미지를 넣지 않는다. 저장은 Web Share(파일)를 먼저 하고, 안 되면 `<a download>`로 한다.
- 이유: 외부 이미지는 CORS 때문에 캡처가 깨진다. 모바일에서는 공유 시트가 가장 자연스럽다.
- 대안과 기각 이유: 토스 웹뷰에서 둘 다 막혀 있으면 앱인토스 SDK 저장 API를 맨 앞에 넣는다 (spec.md 11장).
- 적용 (2026-11-13 사용자 실기기): 토스 앱에서 "저장했어요"가 떴는데 저장이 안 됐다(다운로드가 조용히 무시됨). 위 대안대로 토스 안에서는 `File.saveBase64`를 맨 앞에 둔다. 브라우저는 그대로.

## D-15. localStorage
- 결정: 키는 `bleep:` 접두사를 쓰고, 모든 접근은 `try/catch`로 감싼다. 실패하면 메모리 상태로 동작한다.
- 이유: 웹뷰나 사생활 보호 모드에서 저장소가 막힐 수 있다.
- 대안과 기각 이유: 없음.

## D-16. 광고 (2026-11-13 사용자)
- 결정: 전면형 광고를 짤 저장(공유·다운로드)이 끝난 뒤 띄운다. 하루 1번까지(`bleep:lastAd`), 공유를 취소하면 띄우지 않는다. 배너·보상형은 쓰지 않는다.
- 이유: 저장을 마친 뒤라 흐름을 끊지 않는다.
- 대안과 기각 이유: 보상형("한 번 더 뽑기")은 사용자가 얻는 대가가 너무 작다. 배너는 수익이 낮고 375px 화면을 좁힌다.

## D-17. 시각 변경으로 보상 다시 받기 막기 (2026-11-13 사용자)
- 결정: 보상을 받은 뒤 설정에서 근무 시각을 바꿔도 같은 날 보상은 다시 주지 않는다.
- 이유: 퇴근 후(off)일 때 근무일 키(`todayKey(workEnd)`)는 어떤 시각 설정이든 항상 오늘 날짜다. 그래서 D-09의 `bleep:lastReward` 비교만으로 이미 막힌다. `src/lib/time.test.js`가 30분 간격 모든 출퇴근 조합 × 10분 간격 현재 시각으로 이를 검사한다. 코드 변경 없음.
- 대안과 기각 이유: 근무 시각 변경 횟수 제한·잠금은 필요 없다. 기기 시계를 바꾸는 것은 서버가 없어서 막지 않는다 (D-02).

## D-18. 메인 화면 구성 (2026-11-13 사용자)
- 결정: 메인은 한 화면에 타이머, 가운데 캐릭터, 아래 고정 [도감] [짤 만들기] 버튼. 캐릭터 표정은 근무 진행률로 단계를 나눈다(출근 전 졸림 / 0~50% 무표정 / 50~80% 짜증 / 80~95% 화남 / 95%~ 폭발 직전 / 퇴근 후 후련). 배경은 기기 시각으로 아침 06~11시, 점심 11~18시, 밤 18~06시 3가지이고, 사용자가 그림을 주며 오기 전까지는 그라데이션 (2026-11-13 사용자, 단계별 배경색 안은 대체). 퇴근 순간 1~2초 펑 연출 뒤 지금 보상 창을 띄운다. 퇴근 뒤 처음 열었을 때도 보상과 함께 펑 연출을 한 번 보여 준다. 캐릭터는 분노의 복어(부풀고 가시가 돋다가 펑 터지며 단어 카드를 뱉음), 배경은 사무실 책상 위 어항이며 그림은 사용자가 준다. 도감은 버튼으로 여는 전체 화면.
- 이유: 퇴근이 다가오는 감정을 캐릭터로 보여 주고, 단어가 "터져 나오는" 순간을 만든다.
- 대안과 기각 이유: 코드로 그린 캐릭터·이모지 대신 사용자 그림 (2026-11-13 사용자). 보상 창 대신 말풍선은 화면을 새로 만들어야 해서 기각. 시간대마다 캐릭터도 바꾸는 안은 그림이 18장 필요해서 기각. 진행률 구간 값은 임시이며 화면을 보고 조정한다.

## D-19. 짤 템플릿과 선택 시트 (2026-11-13 사용자)
- 결정: 템플릿은 문장과 색 조합이다(`src/data/templates.json`, 색은 #rrggbb 인라인). 처음 6개, 처음부터 전부 쓸 수 있다. 짤 만들기 화면에서 "템플릿 ▾", "단어 ▾" 줄을 누르면 아래에서 시트가 올라오고, 2열 카드 그리드에서 고른다. 단어 시트 맨 앞의 "단어 없이"를 고르면 단어 자리에 빨간 "삐-"가 들어간다.
- 이유: 캡처 규칙(D-14)대로 그림 없이 글자와 색만으로 다양하게 만들고, 단어가 늘어도(M2) 고르기 쉽게 한다. 인라인 색은 Tailwind가 JSON을 읽지 않아도 되고 html2canvas가 그대로 읽는다.
- 대안과 기각 이유: 모아야 열리는 템플릿은 보상 규칙(D-09)까지 바꿔야 해서 기각. 가로 칩 목록은 단어가 100개를 넘으면 고르기 어렵다.

## D-20. 템플릿 단어 자리는 외치는 말 틀 (2026-11-13 사용자)
- 결정: 템플릿 문장에서 {YY}(단어, 또는 "삐-")는 입에서 터져 나오는 말로 읽히게 쓴다. 예: "저절로 나온다 {YY}", "외쳤다 {YY}!", `"{YY}" 외쳐`. {YY}를 명사로 받는 "{YY} 같네", "{YY} 판정" 같은 틀은 쓰지 않는다. 템플릿을 고치거나 늘릴 때 이 기준을 지킨다.
- 이유: 순화 비속어는 대부분 감탄사라, 명사 틀에 넣으면 "우씨 같네", "제기랄 판정"처럼 어색하다. 틀을 맞추면 단어가 늘어도 그대로 맞는다.
- 대안과 기각 이유: 단어마다 품사를 달고 템플릿을 거르는 방식은 데이터 형식(D-11)과 짤 화면을 바꿔야 해서 기각. 따옴표만 씌우기는 어색함이 남는다.
