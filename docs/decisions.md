## D-01. 화면 스택
- 결정: React 19 + Tailwind CSS v3.4 + Vite, 이미지 캡처는 html2canvas 1.4.
- 이유: 웹뷰 미니앱에 가볍고 익숙한 조합.
- 대안과 기각 이유: Tailwind v4는 기본 색이 `oklch()`라 html2canvas 1.x가 파싱하지 못해 캡처가 실패한다.

## D-02. 서버리스 (2026-11-13 사용자)
- 결정: 백엔드를 두지 않는다.
- 이유: 랭킹·알림·동기화가 없어서 서버가 필요 없다.
- 대안과 기각 이유: 서버를 두면 운영 비용과 심사 범위가 늘어난다.

## D-03. 게스트 (2026-11-13 사용자)
- 결정: 로그인 화면 없이 바로 쓰고, 데이터는 기기 localStorage에만 둔다.
- 이유: 서버가 없고 진입 장벽을 없앤다.
- 대안과 기각 이유: 토스 계정 연동은 서버가 필요하다. 대신 기기를 바꾸면 도감이 사라진다 (spec.md 11장).

## D-04. 범위 밖 (2026-11-13 사용자)
- 결정: 랭킹, 알림, 서버 동기화는 만들지 않는다.
- 이유: 모두 서버가 필요하다 (D-02).
- 대안과 기각 이유: 없음.

## D-05. 디자인 시스템 (2026-11-13 사용자)
- 결정: Tailwind로 만들고, 앱인토스 심사에서 TDS를 요구하면 그때 바꾼다.
- 이유: 요구 여부를 아직 모른다.
- 대안과 기각 이유: 처음부터 TDS를 쓰면 html2canvas 호환을 다시 확인해야 한다.

## D-06. 근무일 (2026-11-13 사용자)
- 결정: 주말·휴일 구분 없이 매일 근무일로 본다.
- 이유: 가장 단순하다.
- 대안과 기각 이유: 요일 설정은 설정 화면과 상태 계산이 복잡해진다.

## D-07. 야간 근무 (2026-11-13 사용자)
- 결정: 퇴근 ≤ 출근이면 근무 시간은 working, 퇴근부터 그날 출근 전까지 off. before는 없다.
- 이유: 그전 코드는 야간 근무자가 off가 되지 않아 보상을 못 받았다.
- 대안과 기각 이유: 퇴근 직후를 before로 보면 보상 시점이 없다.

## D-08. 카운트다운 타이머
- 결정: 다음 정각 초에 맞춘 `setTimeout`을 이어 걸고, 매 틱 `Date.now()`로 다시 계산한다. `visibilitychange`로 가려지면 멈춘다. 매초 다시 그리는 범위는 `memo`로 감싼 `<Countdown>`.
- 이유: 드리프트와 백그라운드 탭 지연을 피하고 리렌더를 줄인다.
- 대안과 기각 이유: `setInterval`은 밀리고, 백그라운드에서 몰아서 실행된다.

## D-09. 퇴근 보상
- 결정: 근무일 키(퇴근 시각의 날짜)를 `bleep:lastReward`에 저장해 1번만 준다. 안 모은 단어 중 common 60 / rare 25 / epic 12 / legendary 3 가중치로 뽑고, 다 모았으면 전체에서 뽑는다.
- 이유: 수집 진행이 보이게 한다.
- 대안과 기각 이유: 완전 무작위는 중복이 많아 모으는 재미가 줄어든다.

## D-10. 보상 누적 없음 (2026-11-13 사용자)
- 결정: 앱을 열지 않은 날의 보상은 사라진다.
- 이유: 가장 단순하다.
- 대안과 기각 이유: 누적은 날짜 계산과 여러 장 보상 화면이 필요하다.

## D-11. 단어 저장 방식 (2026-11-13 사용자)
- 결정: 단어는 많을수록 좋고, 정적 JSON을 코드에 포함한다. 수천 개를 넘어 첫 로딩이 느려지면 별도 JSON을 불러오는 방식으로 바꾸고, 형식은 그대로 둔다.
- 이유: 서버가 없고, 수천 개까지는 번들에 넣어도 충분히 작다.
- 대안과 기각 이유: 원격 DB는 D-02와 맞지 않는다.

## D-12. 단어 수위 (2026-11-13 사용자)
- 결정: 순화 비속어(minced oath), 장난스러운 욕(playful profanity), 순한 욕(soft swear)만 넣는다. 실제 욕설·비하·혐오 표현은 넣지 않는다.
- 이유: 앱인토스 심사 수위.
- 대안과 기각 이유: 없음.

## D-13. 세부 검수 기준 보류 (2026-11-13 사용자)
- 결정: 앱인토스 콘텐츠 기준을 확인한 뒤 정한다. 그전까지는 지금 목록을 유지한다.
- 이유: 기준을 아직 모른다.
- 대안과 기각 이유: 추측으로 기준을 세우면 다시 해야 할 수 있다.

## D-14. 짤 캡처와 저장
- 결정: 캡처 영역에는 외부 이미지를 넣지 않는다. 저장은 Web Share(파일)를 먼저 하고, 안 되면 `<a download>`로 한다.
- 이유: 외부 이미지는 CORS 때문에 캡처가 깨진다. 모바일에서는 공유 시트가 가장 자연스럽다.
- 대안과 기각 이유: 토스 웹뷰에서 둘 다 막혀 있으면 앱인토스 SDK 저장 API를 맨 앞에 넣는다 (spec.md 11장).

## D-15. localStorage
- 결정: 키는 `bleep:` 접두사를 쓰고, 모든 접근은 `try/catch`로 감싼다. 실패하면 메모리 상태로 동작한다.
- 이유: 웹뷰나 사생활 보호 모드에서 저장소가 막힐 수 있다.
- 대안과 기각 이유: 없음.

## D-16. 광고 (2026-11-13 사용자)
- 결정: 전면형 광고를 짤 저장(공유·다운로드)이 끝난 뒤 띄운다. 하루 1번까지(`bleep:lastAd`), 공유를 취소하면 띄우지 않는다. 배너·보상형은 쓰지 않는다.
- 이유: 저장을 마친 뒤라 흐름을 끊지 않는다.
- 대안과 기각 이유: 보상형("한 번 더 뽑기")은 사용자가 얻는 대가가 너무 작다. 배너는 수익이 낮고 375px 화면을 좁힌다.
